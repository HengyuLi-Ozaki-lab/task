# FAQ — `tot` 固有

## Q1. `tot` は何をするモジュール?

`tot` は **オーケストレータ** で, eq / tr / ti / fp / wr / wrx の
各モジュールを 1 つのプロセス内で統合実行します. パラメータ名に
プレフィックス (`eq:`, `tr:`, ...) を付けることで, 適切なサブモジュールに
ルーティングします.

主な用途:

- **平衡 + 輸送 + RF 加熱** を整合的にシミュレーション
- 各サブモジュールの結果を **動的に他のモジュールに渡せる** (例: `eq` の
  q プロファイルを `tr` の輸送計算に反映)
- 単独モジュールを順次呼ぶコードを書く必要がない

## Q2. なぜプレフィックスが必要?

eq, tr, ti, fp, wr, wrx は **同じパラメータ名 (`RR`, `BB`, `NSMAX`)** を
使っています. プレフィックスなしだと `RR` をどのモジュールに渡すべきか
分からないので, 明示的に `eq:RR`, `tr:RR` と書く必要があります.

別解として「全モジュールで `RR` を共有する」設計も考えられますが, モジュール
ごとに微妙に意味が違う場合 (例: eq の `RR` は装置設計値, tr の `RR` は
プラズマ中心) があるため, **明示的に分離** されています.

## Q3. `tot` と `ti` の違いは?

両方ともプラズマシミュレーションを統合する点では似ていますが:

| | `ti` (統合輸送) | `tot` (オーケストレータ) |
|---|---|---|
| 統合方法 | 1 つの方程式系に補助物理を組み込む | 既存モジュールを別々に呼んで結果を受け渡し |
| サブモジュール | 内部実装 (NBI, EC, NF 等を独自実装) | 外部実装を呼ぶ (`wr`, `fp` 等) |
| パラメータ名 | `MODEL_NB`, `MODEL_EC` など | `eq:RR`, `tr:NSMAX` など (プレフィックス) |
| 物理精度 (RF) | 簡略 | フル (`wr`/`wrx` 経由) |
| 物理精度 (高速イオン) | 流体近似 | フル (`fp` 経由) |
| 計算コスト | 中 | **大** (全モジュール展開) |

研究目的で **高精度** が必要なら `tot`, 教育目的で **手早く動かす** なら
`ti`.

## Q4. `Tot()` を作ると裏で何が起きる?

`tot_init` が呼ばれ, 順次:

1. `pl_init` — プラズマ共通モジュール
2. `eq_init` — 平衡
3. `tr_init` — 輸送
4. `ti_init` — 統合輸送 (もしあれば)
5. `fp_init` — Fokker-Planck
6. `wr_init`, `wrx_init` — レイトレース

すべて成功すると `state.<mod>_present = 1` になります. 失敗した
モジュールは present=0 になり, そのプレフィックスのパラメータ設定は
エラーになります.

## Q5. `tot` 内のサブモジュールを単独テストできる?

`Tot()` セッション内では, **特定モジュールだけ** を選んで実行することは
直接できません. ただし他モジュールの計算をスキップする方法はあります:

- 該当モジュールのパラメータを既定のままにする
- 関連スイッチ (`MODEL_*`) を 0 (OFF) にする

完全な単独テストには **単独モジュール** (`Trlib`, `Wrlib` 等) を使う
のが普通です.

## Q6. メモリ不足になる

`tot` は全モジュールの状態を持つため, メモリ消費が大きいです. 概算:

```
tr のメモリ + eq のメモリ + ti のメモリ + fp のメモリ + wr のメモリ + wrx のメモリ
≈ 数百 MB 〜 数 GB
```

特に `fp:NPMAX`, `fp:NTHMAX` を大きくすると一気に数 GB に達します.
対処:

- `fp:NPMAX`, `fp:NTHMAX` を抑えめに (`fp` の FAQ Q3,
  `docs/sphinx/modules/fp/ja/faq.md` を参照)
- `wr:NSTPMAX` を抑えめに
- 不要なモジュールは存在を無視 (該当パラメータを設定しない)

## Q7. 結果が `tot_x2` (CLI 版) と一致しない

回帰テスト `totlib_equivalence` を実行:

```bash
bash test_run/run_tests.sh totlib_equivalence
```

tolerance は `1e-10`. `TOT_RUN_OK` ゲートが立っていないとスキップされます
({doc}`testing` 参照).

## Q8. プレフィックス無しのキーは絶対 NG?

**NG です**. `set_param("RR", 6.5)` は `TotlibInvalidParamError` を
投げます. 必ず `eq:RR`, `tr:RR` などと書いてください.
