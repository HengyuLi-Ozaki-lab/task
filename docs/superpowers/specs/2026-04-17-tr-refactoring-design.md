# TASK/TR モジュール リファクタリング設計書

**日付**: 2026-04-17
**対象**: `tr/` ディレクトリ（46ファイル / 約25,000行 / Fortran 90）
**ブランチ**: 本作業用ブランチ（`fix/tr-dealloc-cleanup` の完了後を起点）

## 1. 目的と前提

### 1.1 目的
- 保守性を引き上げ、既存開発者と新しい参加者の双方が手を入れやすい構造へ改善する。
- 構造・危険箇所の限定的近代化に留め、物理モデルと数値結果を保存する。

### 1.2 非目標
- `tr/trm/trx` の枝分かれ統合（別プロジェクトとして切り出す）。
- 変数名の大文字小文字変更・短縮名のリネーム。
- COMMON block の全撤廃。
- 全面的なユニットテスト (pFUnit 等) 導入。

### 1.3 制約
- 既存開発者の作業ブランチへのマージ競合を最小化する。
- 数値結果は相対誤差 `1e-10`〜`1e-12` 以内で保持する（具体値は Phase 0 で確定）。
- 既存の `USE TRCOMM` インタフェースは可能な限り維持する。

## 2. 現状サマリ

- 巨大ファイル: `trcoef.f90` 2026行、`trrslt.f90` 1876行、`trexec.f90` 1767行、`trcalc.f90` 1391行。
- `trcomm.f90`: 約103個のグローバル変数を集約。
- `USE TRCOMM`（ONLY 句なし）で参照しているファイル: `trfout.f90`, `trloop.f90`, `trparm.f90`, `trrslt.f90`。
- エラー処理: `GOTO` ラベルジャンプと `WRITE(6,*) 'XX ERROR...'` が散在し、統一されていない。
- `tritg.f90` に COMMON block が9個残存。
- 既存テスト資産: `test_run/` に横断テスト基盤あり、`tr_iter01` が1件登録済み。

## 3. 基本方針

「構造 + 危険箇所のみ近代化」（Option B）。既存スタイル（大文字変数、既存命名、モジュール境界）は原則保存する。

**進め方は低リスク順（非侵襲的な改善から）**。API を変えない内部整理を先に行い、段階的に踏み込む。各フェーズは独立した PR として扱い、いつでも中断・差し戻し可能にする。

## 4. テスト戦略

リファクタリング前に挙動固定の回帰テスト基盤を整える。

### 4.1 層構成
1. **層1（ゴールデンテスト）**: 代表入力で走らせ、最終プロファイル・収束履歴・全体量を数値ベースライン化。
2. **層2（チェックポイント比較）**: 必要に応じて、特定ステップでの内部配列 `X/Y/Z` をダンプし比較。
3. **層3（ユニットテスト）**: 構造改善後に分離できたモジュールから順次追加。本設計の範囲外。

### 4.2 採用
Phase 0 で層1のみ実装。層2はデバッグ時の武器として枠だけ用意し、必要に応じて有効化。

### 4.3 比較仕様
- 比較対象: 最終時刻のプロファイル（`RN, RT, RU, QP, AJ` など）と全体量（`WPT, AJT, BETA0, Q0` 等）。
- 許容誤差: 相対誤差 `1e-10` を第一候補とする。Phase 0 で `-O0` 実行時の run-to-run 再現性を測り、必要に応じて緩める。
- 環境依存対策: コンパイラ最適化オプションを固定（`FFLAGS=$(OFLAGS)` を明記）。

## 5. フェーズ計画

各フェーズ単位で PR を切り、マージ後に次へ進む。

### Phase 0: 回帰テスト整備（1〜2週）
- `test_run/test_definitions.conf` に少なくとも以下を追加:
  - `tr_iter01`（既存）
  - `tr_m0904`（`tr.M0904.in` 系）
  - `tr_tst2`（`tr.TST-2.in` 系）
- 比較スクリプト（Python または bash + numpy）を新規追加し、`test_output/` のテキスト出力 or 新設するダンプファイルを前回結果と比較。
- ベースライン出力を `test_run/baselines/` にコミット。
- コンパイラ・最適化オプションを CI 側で固定する仕組みを用意。
- **既存コードへの影響**: ゼロ。

### Phase 1: `USE TRCOMM` への ONLY 句付与（数日）
- 対象ファイル: `trfout.f90`, `trloop.f90`, `trparm.f90`, `trrslt.f90`。
- コンパイラの未使用シンボル警告を頼りに、実際に参照している変数のみを ONLY 列挙。
- **挙動不変**を回帰テストで確認。
- **既存コードへの影響**: 他ファイル無変更。

### Phase 2: `trcomm.f90` の論理 submodule 分割（約1週）
- 分割単位（案）:
  - `trcomm_const`（物理定数 `PI`, `AEE`, `RKEV` 等）
  - `trcomm_param`（`RR`, `RA`, `BB`, `DT` 等の入力パラメータ）
  - `trcomm_ctrl`（`NT`, `NRAMAX`, 制御変数）
  - `trcomm_mtx`（`XV`, `YV`, `AX`, `X` 等の行列変数）
  - `trcomm_profile`（`RN`, `RT`, `AJ` 等のプロファイル変数）
  - `trcomm_globals`（`WPT`, `AJT` 等のグローバル量）
- **互換性**: `MODULE TRCOMM` は上記を `USE ...; PUBLIC` で再エクスポートするラッパに変更。既存の `USE TRCOMM, ONLY: ...` は一切変更不要。
- `ALLOCATE_TRCOMM` / `DEALLOCATE_TRCOMM` は責務に応じて各 submodule に分割しつつ、最上位 `TRCOMM` から呼び出し順序を制御。
- **既存コードへの影響**: USE 文の変更なし。内部構造のみ変わる。

### Phase 3: `trrslt.f90`（1876行、12サブルーチン）の分割（1〜2週）
- 出力系サブルーチンを責務別モジュールに切り出す。
  - 物理量計算系（`TRGLOB` 相当）
  - 時系列保存系
  - 画面出力・テキスト出力系
- **選定理由**: 副作用が「値を書き出す」ことに限定されており、物理数値への波及リスクが他の巨大ファイルより小さい。
- 呼び出し元は `USE` 文の追加のみで対応（関数名は維持）。
- **既存コードへの影響**: `trrslt.f90` を呼ぶ側での USE 文追加のみ。

### Phase 4: `trexec.f90` の `GOTO` 整理（約1週）
- `trexec.f90:110, 114, 120, 125` 等の収束判定 `GOTO` を named loop の `EXIT` または小さなヘルパ関数に置換。
- `'XX ERROR IN TRLOOP'` 系の WRITE + RETURN パターンを、共通エラーハンドリング関数に集約（関数名・IERR 規約は保持）。
- **既存コードへの影響**: `trexec.f90` 内部のみ。インタフェース不変。

### Phase 5: `trcoef.f90` の主要ルーチンをモジュール化（約2週）
- `TRCFDW`（乱流拡散）, `TRCFNC`（ネオクラシカル）, `TRCFET`（電気抵抗率）, `TRCFAD`（ad-hoc モデル）をそれぞれ独立モジュールに抽出。
- 物理モデルを変更する修正は一切含めない（行・式の位置を変えるのみ）。
- 抽出単位で回帰テストを実行し、数値一致を確認してからマージ。
- **選定理由**: 物理計算の中核かつ最大ファイル。最終段階に据え、テスト網が整ってから着手する。
- **既存コードへの影響**: 呼び出し側の USE 文追加。関数シグネチャ不変。

### 合計目安
約 7〜10 週（Phase 0〜5 を直列で実施する場合）。並列化は避け、1フェーズずつ確実にマージする。

## 6. リスクと緩和策

| リスク | 影響 | 緩和策 |
|---|---|---|
| 数値結果が微妙に変わる | 物理研究結果への疑義 | Phase 0 の回帰テストで即検知。ダメなら即 revert |
| 既存開発者の作業ブランチとの競合 | マージ地獄 | フェーズを小さく切り都度マージ。`trcomm.f90` は Phase 2 の1回のみ触る |
| コンパイラ依存の再現性劣化 | 偽陽性のテスト失敗 | 最適化フラグを固定。許容誤差を実測値から決める |
| Phase 5 で物理的に誤った抽出 | 物理不正 | 変更は「移動のみ、式改変なし」を PR レビューで厳守 |
| 回帰テストのケース不足 | 未検出の挙動変化 | ITER/M0904/TST-2 の3系統を最低ライン。追加要望があれば随時拡張 |

## 8. 受け入れ基準

- Phase 0 完了時: 3ケース以上の回帰テストがグリーンで CI 化されている。
- 各 Phase 完了時: 全回帰テストがグリーン（許容誤差内）。
- 全 Phase 完了時:
  - 呼び出し側での `USE TRCOMM`（ONLY 句なし）参照が 0 件（`trcomm` ラッパ内部で submodule を再エクスポートする用途は除く）。
  - `trcomm.f90` が単一の巨大モジュールではなく、論理的な submodule 群として構成されている。
  - `trrslt.f90`, `trcoef.f90`, `trexec.f90` の各々が責務別に分割されている。
  - 数値結果が Phase 0 で確定した許容誤差以内で維持されている。

## 9. 未確定事項

- 回帰テストの具体的比較項目（プロファイルのどの時刻・どの変数を含めるか） → Phase 0 で確定。
- 許容誤差の最終値 → Phase 0 で `-O0` 実行時の run-to-run 差から決定。
- Phase 2 の submodule 境界の細部 → 実装着手時に `trcomm.f90` のブロック構造を精査して最終決定。
