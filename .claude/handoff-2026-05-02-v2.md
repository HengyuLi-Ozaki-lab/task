## 重要な設計判断 (plan からの逸脱)

### A. DSRHO は global ではなく local

Plan §5.4 で `DSRHO` を TRCOMM 経由 import する想定だったが, 実際は `trprof.f90` と `trrslt_globals.f90` で local に `DSRHO(NR) = DVRHO(NR) / (2π·RR)` と計算されているだけで, TRCOMM 経由で公開されていない. 解決:

- USE 句に `DVRHO, PI, RR` を追加 (DVRHO は既存)
- 注入式を `DSRHO * DR` ではなく `DVRHO * DR` で書き直し
- normalization の係数に `* 2.D0 * PI * RR` を inline で乗じる
- 結果: 数学的には同値. Smoke test で AJRFT=1.0 の精度 1e-15 を確認済

### B. trprf 早期 return guard の拡張

Plan §5.4 で言及していなかったが, `trprf.f90:19` の `IF(PECTOT+PLHTOT+PICTOT.LE.0.D0) RETURN` 早期 return が, EXTERNAL_DRIVEN_I のみ設定したケースで subroutine をスキップしてしまう問題を発見. 解決: guard を `... .AND. EXTERNAL_DRIVEN_I.EQ.0.D0` で AND 拡張. これで PEC/PLH/PIC=0 + EXTERNAL_DRIVEN_I≠0 でも routine が走る (PEC/PLH/PIC 計算は zero contribution で harmless に通過).

### C. test_ffi.py レイアウト test の追従

C struct に AJRFT (8 bytes) を追加したので, `sizeof(TrStateC)` が 8 bytes 増. test_ffi.py の `test_size_matches_header_math` の `exp_core` を `13 * 8 + ...` → `14 * 8 + ...` に更新. test_has_expected_fields にも "AJRFT" を追加. これは Phase 1 commit に bundle 済 (Phase 3 ではなく).

### D. trlib `validate()` wrapper は既存

Plan Task 1.10 で「無ければ追加」想定だったが, `python/trlib/trlib.py:253` に既存. wrapper 追加は不要だった.

### E. Pre-existing flaky test (NOT my fault)

`python/trlib/tests/test_property_boundary.py::test_NSMAX_in_range` が NaN で fail する. これは私の変更前 (chore base) でも再現. CLAUDE.md の "heap-layout-flaky" カテゴリ. Phase 4 の pytest sweep では `--ignore=python/trlib/tests/test_property_boundary.py` で除外して進める想定.
