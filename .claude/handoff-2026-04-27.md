## 重要な設計上の注意点 (新セッションで尊重すべき)

### A. CLAUDE.md の pre-push gate

`docs/sphinx/CLAUDE.md` ではなく **リポジトリ root の `CLAUDE.md`**
が指針. 要点:
- push 前に code-review エージェントを走らせる
- pre-push marker (`REVIEW_OK_<sha>`) を `git common dir` に置く
- `--no-verify` 等は禁止
- 等価性テストの `@pytest.mark.skip` は禁止

### B. macOS 制限

- `lib*api.so` のビルドは私の Makefile 修正で可能
- ただし dlopen 後の **API 利用面でのエラー** は API 仕様問題 (例: ti は
  PA/PZ/PN/PT 配列を埋めないと `ierr=3`, wr/wrx は RKR0/ANGZ 等の入射
  条件不足で `ierr=3`)
- これらは「ビルド問題」ではなく `applications.md` 風のラッパーで吸収する想定

### C. cross-module reference

- 各モジュール = 独立 Sphinx project
- `{ref}\`<other-mod/foo>\`` 形式は **動かない** (undefined label)
- plain text + ファイルパスで表記する慣例 (skill にも記載)

### D. 文字コード

- en ページで `〜` (U+301C) は使わない (DejaVu フォントに無い → PDF で
  消える). ASCII `~` を使う.
- ja は xeCJK で問題なし

## ピンポイントで覚えておくべき設計判断

- **eq `mode=0`**: `EQCALC` (解析 GS 解) + `EQCALQ` (post-process) を fuse
  したのは, CLI の `R` だけだと `qaxis` 等が空で出力されてしまうから.
  `R` → `F` 連続実行と等価.
- **graphics stubs**: Linux ld は lazy 解決, Apple ld は eager 解決
  の違いで, .so に未定義シンボルが残ると Apple では dlopen 失敗. 全
  graphics 関数を no-op スタブとして自前定義することで吸収.
- **gsaf, bpsd は `.gitignore`**: `setup.sh` が clone する外部依存. 誤って
  vendoring しないため `.gitignore` に `/bpsd/` `/gsaf/` を追加済み.
- **PR 作成はまだ**: ブランチ名は `chore/pre-push-hook-worktree-compat`
  (元の意図) のままなので, master へマージするときは PR タイトルや
  ブランチ名を整えるか相談が必要.
