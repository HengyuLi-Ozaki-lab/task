## 重要な発見 (本セッション)

### A. handoff の "rc=3" は stale だった

handoff 2026-04-29 §E は「`test_tot_ht6m_short` が rc=3 (CALCULATION_FAILED) で失敗する原因は **PP0 ではない**」「fixture-driver divergence 詳細未調査」と書いていた. 実際に検証すると **rc=3 は再現せず**, eqdata-HT6M を staging するだけで 1e-10 PASS. 理由:

1. `tot_api_run` (`tot/tot_api.f90:178-199`) は `tr_api_run` のみを呼ぶ. EQCALC は呼ばない
2. 標準 driver の `eq → r → s` は EQCALC + EQSAVE で `eqdata-HT6M` を生成
3. Python pipeline は EQCALC を持たないが, 標準 driver が生成した `eqdata-HT6M` を tr_prep (MODELG=3) が読み込めば数値一致
4. PP0 は eq side の pressure-profile scalar — EQCALC 入力なので Python 側に passthrough する経路が無い

handoff の "rc=3" は別の test 状態下 (例: stale eqdata or 異なる code revision) の観察と推測される. **handoff の主張は verify before debug** が教訓.
