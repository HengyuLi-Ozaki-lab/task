## 重要な設計上の注意点 (新セッションで尊重すべき)

### A. CLAUDE.md の pre-push gate

`docs/sphinx/CLAUDE.md` ではなく **リポジトリ root の `CLAUDE.md`**
が指針. 要点:

- push 前に code-review エージェントを走らせる
- pre-push marker (`REVIEW_OK_<sha>`) を `git common dir` に置く
  (`touch "$(git rev-parse --git-common-dir)/REVIEW_OK_$(git rev-parse HEAD)"`)
- `--no-verify` 等は禁止
- 等価性テストの `@pytest.mark.skip` は禁止
- Codex review (`codex:codex-rescue`) も走らせるとなお良い (今後追記予定)

### B. macOS 制限

- `lib*api.so` のビルドは Makefile の OS 分岐で対応済 (uname -s)
- ただし dlopen 後の **API 利用面でのエラー** は API 仕様問題 (例:
  ti は PA/PZ/PN/PT 配列を埋めないと `ierr=3`, wr/wrx は RKR0/ANGZ
  等の入射条件不足で `ierr=3`)
- **eq の analytic GS 解 (mode=0)**: `RB` (壁半径) のデフォルトが
  1.2 のままだと, ITER スケール (RA=2.0) で `RB.LT.RA` → EQMAGS が
  PAUSE する. auto_setup では `params.setdefault("RB", params["RA"]*1.2)`
  で自動算出している
- **library-reachable PAUSE/STOP**: pytest 実行中に Fortran の PAUSE
  に当たると stdin 待ちでハング. 範囲を狭めるか, `eqsub.f90` の
  PAUSE 文を `RETURN` に置換する PR を別途 (issue #142 関連)

### C. cross-module reference

- 各モジュール = 独立 Sphinx project
- `{ref}\`<other-mod/foo>\`` 形式は **動かない** (undefined label)
- `{doc}\`<other-mod/foo>\`` も同様 (unknown document warning)
- plain text + ファイルパスで表記する慣例
- 既存問題: `portal:common-architecture` への {ref} が残っている
  (上記 残作業 #3)

### D. 文字コード

- en ページで `〜` (U+301C) は使わない (DejaVu フォントに無い → PDF で
  消える). ASCII `~` を使う
- ja は xeCJK で問題なし
- code fence lexer: `json` を使用 (`jsonc` は MyST が認識しない)

### E. state.scalars のキーは小文字

- eq: `raxis, qaxis, qsurf, betat, betap, ...` (小文字)
- 大文字でアクセスすると KeyError
- ただし MCP の `handle_get_state()` の応答は大文字に変換されている
  (例: `RAXIS = 3.0709`)
- doc 内コードでは小文字を使うこと

### F. Codex review

- pre-push gate で general-purpose code-reviewer に加えて `codex:rescue`
  も走らせるのが推奨 (前セッションで気付いた)
- 起動: `Agent(subagent_type="codex:codex-rescue", prompt="...")`
- 認証切れ時は `! codex logout && codex login` (ユーザに promp)
